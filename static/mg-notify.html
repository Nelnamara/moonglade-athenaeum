mg-notify — toasts & the Job Tracker

One <script src>, four systems: Toast (corner notices), Jobs/JobsCard (the Activity tracker), and Ach (the Folio of Honors + celebrations). The file styles itself; a host adds only the two Activity anchors below — reproduced verbatim from the gallery's own pages.

Toast — Toast.show({kind, title, msg, icon})

Job Tracker — Jobs.track() / JobsCard.open()

The tracker is server-fed: registration and phase polling live in the served app. With no server behind this page the Activity FAB stays hidden and the opened tray is an empty shell — the chrome boots, the rows need the real app. Served at /static/mg-notify.html, these same buttons drive the live tracker.

events: (none yet)
  1. ok reads emerald, err reads red and warns; the neutral kind takes any icon glyph (the app uses it for undo-able deletes).
  2. Toasts stack newest-on-top in #mg-toasts and expire on their own; their z-index deliberately clears every full-screen overlay in the app.
  3. The Activity FAB below-left is the app's own anchor markup; opening it shows the tray card (JobsCard), which is where tracked generations live.
  4. Rows are server-fed: Jobs.track() registers the task, then Jobs.poll() walks /api/task-status phases (done/failed terminal, anything else keeps polling) — so rows appear only under the served app; here the open tray stays an empty shell by design.
  5. The mid-screen achievement celebration is not host-callable (Ach exposes open/close/poke/setUnleash/tab/search only) — it fires off the server's achievement feed, so it belongs to the served app, not this page.
